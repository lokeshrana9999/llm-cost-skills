# llm-cost-skills

Three skills that let a coding agent find where an app spends money and time on LLM calls, then write a priced, ranked report with each finding tied to a `file:function`.
It runs locally on Python 3.8+ (standard library only, no install, no network); no data leaves your machine.

## What you get

The top of a report, from **made-up data** (generated by `examples/make_sample.py`, not from any real app):

```
# $20.45-$54.41 a month (8.4-22.3% of spend) can go without changing model output, out of $244 a month; up to $113 more depends on evals
Synthetic data: every row is marked synthetic; no real system produced these numbers. **Spend is a floor: 28 calls on 1 route have no token usage logged.**

- **Do first:** turn on prompt caching on app/extract.py:parse_invoice: n=800 calls, $12.66-$18.98 a month after de-duplication, MECHANICAL.
```

Full made-up report: [examples/sample_report.md](examples/sample_report.md) (`--scope stay`) and [examples/sample_report_open.md](examples/sample_report_open.md) (`--scope open`: the same headline, plus a section on other providers).

## Install

```
git clone https://github.com/lokeshrana9999/llm-cost-skills
cd llm-cost-skills
```

Use `python3` instead of `python` below if `python` is not Python 3 on your machine.

- **Claude Code:** start it with this folder as a plugin: `claude --plugin-dir /path/to/llm-cost-skills` (the folder has `.claude-plugin/plugin.json` and `skills/`). The skills need `scripts/` and `delegation/` next to them, so use the whole folder; do not copy `skills/` on its own.
- **Codex, Cursor, other agents:** run your agent from inside this folder and open `AGENTS.md`; it points to the skill files. Tell the agent: "audit my LLM usage using the skills in this folder".

## Try it on the sample in one minute

The sample rows and routes in `examples/` are made up. This writes the report you saw above and checks the calculator:

```
python scripts/calc.py examples/sample_rows.jsonl --routes examples/sample_routes.json --scope stay -o examples/sample_report.md
python scripts/calc.py examples/sample_rows.jsonl --routes examples/sample_routes.json --scope open -o examples/sample_report_open.md
python scripts/test_calc.py
```

## The three skills

| Skill | Does | Writes |
|---|---|---|
| `llm-scan` | finds every call site (SDK, CLI subprocess, HTTP, decision models) and the app's usage logs | `work/<repo>/routes.json` |
| `llm-capture` | writes an adapter from the app's logs to the row schema, or gives you an optional logging shim | `work/<repo>/adapter.py`, `rows.jsonl` |
| `llm-diagnose` | runs `scripts/calc.py`, joins findings to routes, adds "where in code" | `work/<repo>/report.md`, `diagnosis.md` |

Ask "audit my LLM usage" or "why is my LLM bill high"; each skill reads one file from `delegation/` for which helper does which step. `llm-diagnose` first asks once: "Stay with your current AI providers, or open to cheaper options from other providers?" (default: stay) and passes the answer as `--scope`.

## Provider scope and the other findings

- **`--scope stay`** (default): every action stays with the providers in your data: caching, trimming, caps, batching, failed-call fixes, a smaller model at the same provider. The report header says which scope ran.
- **`--scope open`**: adds a separate section, "Other providers (open scope, HYPOTHESIS)". For each route it lists up to 3 cheaper models of the same or one lower `class` (from `prices.json`) at other providers, with the route's spend re-priced at their list prices ($0 low end), the switching cost (new vendor and key, your data goes to a new provider) and the eval to run (replay 100-200 logged calls). A route with a tiny verdict as output (p50 of 5 tokens or less on 50+ calls, or `decision_shaped: true` in routes.json) also gets the cheapest priced decision model, as a gate **net of its own calls** (assumption A2: it passes 10% of calls on to the current model). Candidates are in no total: the headline and action table are identical under both scopes. Candidates come only from the models priced in `prices.json`; no model judges equivalence.
- **Unused tool schemas** (needs `tool_schema_tokens` and `tool_calls`): tool definitions sent on 90%+ of a route's calls with no tool call, across 2+ sessions. MEASURED dollars (schema tokens x calls at the cached rate if cached tokens cover the schema, else the uncached input rate); the action, "drop or defer unused tool definitions", is a HYPOTHESIS.
- **Spirals**: a task above 2.5x its route's median calls or tokens with 2+ failed calls. MEASURED spend and count; a route needs 20+ tasks, else "not enough tasks".
- **Low evidence**: a finding whose calls carry `session_id` and span fewer than 3 sessions is marked "low evidence" in the action table.
- Tool-schema and spiral figures are outside the totals (they overlap caching and failed-call waste).

## Privacy rules

- Rows hold numbers and short opaque values only: model, token counts, times in ms, route, success, hashed ids. Never prompts, answers, transcripts or user text.
- Task, session and prefix ids are hashes; `calc.py` hashes task and session ids again before printing.
- All outputs go under `work/<repo>/` in this pack. The agent never writes into your repo and asks before suggesting a code change.
- `python scripts/check_rows.py work/<repo>/rows.jsonl` fails on any column outside the schema or any long or multi-word text value.
- `python scripts/privacy_check.py work/<repo> --phrases-file <temp file>` searches the outputs for phrases and raw ids you list (one per line) and reports which line hit which file, never the text. Keep the phrases file outside `work/` and delete it afterwards.

## Labels, and where numbers come from

All numbers come from `scripts/calc.py`; no model computes them. Each finding carries one label:

- **MEASURED**: read directly from your data.
- **MECHANICAL**: follows from provider price rules and observed timings; does not change model output.
- **HYPOTHESIS**: needs a replay or eval on your own calls before you act.

## Row schema (rows.jsonl)

One JSON object per model call. `input_tokens` counts cache reads and writes as part of the input (pass `--input-excludes-cached` if your export counts them separately).

| Column | Required | Unit | What it unlocks |
|---|---|---|---|
| `model` | yes | text | pricing; an unknown model is reported as unpriced, never guessed |
| `input_tokens` | yes* | tokens | spend |
| `output_tokens` | yes* | tokens (0 allowed) | spend |
| `route` | no | `file:function` | per-route findings and "where in code" |
| `timestamp` | no | epoch seconds or ISO 8601 string | window length, monthly projection |
| `cached_input_tokens` | no | tokens | cache reads priced at the cached rate |
| `cache_write_tokens` | no | tokens | 5-minute cache writes |
| `cache_write_1h_tokens` | no | tokens | 1-hour cache writes (priced at 2x input) |
| `ttft_ms` | no | ms | time to first token, TTFT p95 |
| `latency_ms` | no | ms | speed and slow-call views |
| `success` | no | true/false | failed-call and retry waste |
| `streamed` | no | true/false | picks the latency view versus the back-office view |
| `task_id` | no | hashed id | per-task cost, top-5% task share |
| `session_id` | no | hashed id | conversation growth, cache writes after a session's first call |
| `prefix_hash` | no | hashed id | repeated-prefix and prompt-caching findings |
| `prefix_tokens` | no | tokens | size of the repeated prefix |
| `prefix_hash_kind` | no | `content` or `structural` | the report says when the hash is structural (route, model, process id; no prompt text) |
| `stateless` | no | true/false | skips trimming and session-growth for routes whose calls stand alone; `llm-capture` copies it from `routes.json` |
| `usage_missing` | no | true | the call happened but the log has no usage; needs no token columns, is counted, left out of spend, and the report says spend is a floor |
| `logged_cost_usd` | no | USD | a logged-versus-priced check; it warns the logged value may be cumulative |
| `tools_defined` | no | count | tools sent in the request (shown in the unused-tool-schema table) |
| `tool_schema_tokens` | no | tokens | size of the tool definitions in the request; with `tool_calls`, unlocks the unused-schema finding |
| `tool_calls` | no | count | tool calls in the response (`0` means the schema was sent and unused) |
| `synthetic` | no | true/false | marks made-up data; the report says so under the headline |

\* not needed on a row with `usage_missing: true`.

`python scripts/calc.py rows.jsonl [--routes routes.json] -o report.md` also takes:

- `--routes`: the scan's `routes.json`; adds "Scan-only findings (UNMEASURED, no dollars)": `usage_gaps` and live routes with no priced rows. Route fields: `cache_markers` (`explicit|implicit|none|unknown`), `live` and `user_waits` (true, false or `"unknown"`), `stateless`, and `kind: non_llm` for calls out of scope.
- `--scope stay|open` (default `stay`): see "Provider scope" above. `decision_shaped` (true, false or `"unknown"`) is also read from routes.json.
- `--prices FILE`, `--view auto|latency|backoffice|both`, `--ttft-budget-ms N`, `--window-days N`, `--label TEXT`, `--input-excludes-cached`.

## Limits

- `scripts/prices.json` is dated and marked unverified: check it against the providers' pricing pages. Each model carries a `tier` (same-provider routing) and a `class` (`decision`, `small`, `mid`, `frontier`; open-scope candidates). Add aliases there for names such as `anthropic/<model>-20250514`.
- It reads logs only. Quality is not in them, so anything labelled HYPOTHESIS needs an eval on your own calls.
- A window under 7 days gets a warning at the top; weekday and weekend patterns are missing.
- No p95 is printed for a group under 200 calls.
